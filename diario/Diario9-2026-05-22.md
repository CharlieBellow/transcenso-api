Construção da Camada de Entrada (HTTP):
"Implementei o CreatePersonController e o integrei ao HttpModule. Compreendi como os decorators do NestJS (@Controller, @Post, @Body) mapeiam as rotas que o Front-end irá consumir. Ao importar o DatabaseModule para dentro do HttpModule, fechei o fluxo de injeção: o Controller recebe a requisição, chama o Use Case, que por sua vez utiliza o repositório do Prisma para salvar no banco."


Isolamento de Contratos de Entrada (Request DTOs):
"Decidi não reutilizar o PersonProps no Controller para evitar vazamento de escopo do Domínio e impedir que campos internos (como createdAt ou slug) fossem expostos ao Front-end de forma insegura. Adotei a criação de uma pasta dtos dentro da camada http para centralizar as interfaces de requisição (CreatePersonBody). Essa estrutura me permitirá exportar facilmente esses tipos para o Front-end no futuro, mantendo a consistência dos dados."


Organização de DTOs de Entrada:
"Optei por centralizar os contratos de requisição de uma mesma entidade (Create e Update) em um único arquivo chamado personRequests.ts. Compreendi que o DDD preza pelo desacoplamento entre as camadas, mas confere flexibilidade na organização física dos arquivos de Infra. Utilizei o recurso Partial do TypeScript para otimizar o tipo de atualização, reaproveitando a estrutura de criação e mantendo o código DRY."


Incompatibilidade de Versões no Docker (PostgreSQL Upgrade):
"Bati no erro P1001 do Prisma devido ao container do banco estar em loop de reinicialização. Identifiquei pelos logs do Docker que os arquivos locais persistidos pertenciam ao PostgreSQL 15, enquanto o container atual utilizava a versão 16. Resolvi o conflito limpando os volumes antigos com docker compose down -v e recriando o banco do zero. Compreendi que atualizações de versão de imagem de banco exigem a limpeza ou migração dos volumes de dados físicos."



Migração de Configuração do Prisma (Padrão Prisma 7):
"Enfrentei a depreciação da propriedade url dentro do arquivo schema.prisma. Aprendi que nas versões recentes do Prisma, a responsabilidade de conexão foi isolada do arquivo de modelagem. Adaptei a arquitetura criando o arquivo central de configuração prisma.config.ts para a execução das ferramentas de CLI (Migrate) e injetei explicitamente a DATABASE_URL no construtor do PrismaService para o runtime da aplicação NestJS."

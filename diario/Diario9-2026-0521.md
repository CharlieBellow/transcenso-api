Relacionamentos e Enriquecimento de DTOs:
"Defini que o Front-end deve sempre receber objetos aninhados para dados relacionados (gender e sexuality), mas sem metadados como datas de criação. Para respeitar o isolamento da Entidade no DDD, adaptei o método toDTO para receber esses dados externos como parâmetro. O Caso de Uso ficou responsável por orquestrar a busca desses dados nos repositórios e injetá-los no DTO final, garantindo uma resposta limpa e completa para a API."


Fechamento do Fluxo de DTO Aninhado:
"Validei que a lógica do meu Caso de Uso já realiza o enriquecimento dos dados buscando as relações de Gênero e Sexualidade antes de retornar. Ao sincronizar o método toDTO da Entidade para aceitar esses parâmetros, o TypeScript validou o contrato do PersonDTO com sucesso, garantindo que o Front-end receba a estrutura de objetos aninhados necessária."
